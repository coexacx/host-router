# 自动容量管理（0.1.1）

默认启用自动容量管理。规则数量与连接数量分别计算：增加域名规则不会为每条规则预先分配连接。一个监听地址上的不同规则共用进程的资源预算。

## 检测与调整

内核启动时读取实际内存、可用内存、CPU 可用核数、进程文件描述符限制，以及 cgroup v1/v2 中可见的本级和上级内存、CPU 限额。支持容器的挂载根映射及非默认 cgroup 挂载路径。

每 2 秒更新一次资源状态。系统文件读取放在阻塞工作线程中；转发数据路径不扫描进程、文件描述符或系统文件。每个新会话做一次额度检查，UDP 缓冲区只读取缓存的额度。

- 内存：连接估算预算最多使用有效内存的 60%，另扣基础开销和队列预算；当前可用内存不足时继续收紧，为系统和其他服务留出空间。
- TCP、QUIC 共用预算，分别按每会话 256 KiB、384 KiB 作准入估算，避免将两种协议的单独额度相加。
- 文件描述符：为 TCP 的两个 socket、两组 splice pipe，以及监听、DNS、控制接口预留额度。增加监听地址后重新计算预留。
- CPU：握手并发和新建速率随可用 CPU 调整。系统 CPU 持续达到 95%，或进程/受限 cgroup 持续达到其可用 CPU 的 90%，连续 3 次采样后收紧容量；短暂峰值不会触发。
- 内存严重紧张或关键采样失效时暂停新会话。健康状态连续保持 5 次采样后，容量每次恢复 10 个百分点，避免反复跳变。
- 降低容量不会主动关闭已有连接。超过新额度时，已有连接可以继续，新会话暂时被拒绝。
- TCP 拒绝路径加入短暂异步退避；不会为每个被拒绝连接打印日志，减少异常流量造成的额外 CPU 和磁盘开销。

进程 CPU 百分比按其可用 CPU 额度与内核的 2 个转发工作线程中较小值归一化，避免多核主机掩盖转发线程饱和。压测报告中“100% 等于占用一个 CPU 核”的统计口径与这里不同。

## 查看状态

菜单顶部显示自动/手动模式及 TCP、QUIC 当前使用量/有效上限。菜单「转发设置 → 容量与负载详情」显示完整信息，也可运行：

~~~bash
host-router status
host-router capacity-plan
~~~

关键字段：

| 字段 | 含义 |
| --- | --- |
| capacity.mode | auto 或 manual |
| capacity.pressure | normal、cpu、memory、memory_critical、recovering、sensor_unavailable |
| capacity.resources | 有效内存、剩余内存、CPU、文件描述符限制 |
| capacity.effective | 当前准入上限、共用内存预算、握手和新建速率 |
| capacity.ceilings | 配置允许的绝对上限 |
| capacity.admission_rejected | 自动控制器累计拒绝的新会话数 |
| capacity.samples | 已完成的运行时资源采样次数 |

TCP 与 QUIC 的显示上限不能相加：两者仍共享内存和文件描述符预算。上限代表准入额度，不代表机器能以同样吞吐量承载这么多满速连接。

## 手动上限与旧版兼容

配置中的 auto_capacity 默认为 true。全新配置的绝对上限为：

~~~json
{
  "auto_capacity": true,
  "max_tcp_connections": 65536,
  "max_udp_sessions": 16384,
  "max_connections_per_ip": 4096,
  "max_pending_handshakes": 1024,
  "udp_queue_bytes": 268435456
}
~~~

上面仅展示资源字段，实际配置仍需保留 rules 等字段。自动模式会在这些上限内计算可用额度，不会直接放行全部上限。

升级保留原配置中明确填写的数字。若旧配置填写了 TCP 1024，这仍是上限；如需扩大，可停止服务后提高该字段，再启动服务。auto_capacity 和这些资源字段的手动更改需要重启；运行中的自动调整不需要重启。

设置 auto_capacity 为 false 可使用固定配置额度，关闭自适应控制。普通 UDP 仍被拒绝，QUIC 仍有固定新建速率保护。

## 服务资源边界

安装器只配置 host-router 服务：文件描述符上限取系统允许值与 1048576 中的较小值，MemoryHigh 取安装时有效内存的 70%，MemoryMax 取 80%，CPUWeight 设为 80。不更改整机 sysctl、防火墙、其他服务或 CPU 硬配额。已有自定义 systemd drop-in 仍按 systemd 的优先级生效。

MemoryHigh 是回收/节流阈值，MemoryMax 是硬边界。硬边界在异常情况下可能触发本服务 OOM 和重启，不保证已有连接永不中断。swap 不计入可用连接预算。

这些限制依据可见的 Linux 资源信息，并包含运行时余量；不同内核、网络缓冲区、慢速对端和其他应用的突发开销仍会影响实际容量。不能把自动估算视为整机绝不会过载的保证。没有增加透明代理、源 IP 伪装或修改其他应用的配置。

cgroup 语义参考 [Linux cgroup v2 文档](https://docs.kernel.org/admin-guide/cgroup-v2.html)；采样字段参考 [Linux procfs 文档](https://www.kernel.org/doc/html/latest/filesystems/proc.html)。

## 测试

tests/capacity.py 在独立临时 systemd 服务中设置 256 MiB 内存软限额、320 MiB 硬限额、0.5 CPU 和 2048 个文件描述符；降低该服务的软内存阈值并在该 cgroup 内产生有限 CPU 压力，验证拒绝新连接、保持已有 TCP/QUIC 会话及渐进恢复。测试结束自动清理临时服务，不改变整机限额。
