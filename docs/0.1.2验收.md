# 0.1.2 异常网络与可靠性验收

测试日期：2026-10-02。候选版本：0.1.2；对照：已发布的 0.1.1。

## 修改范围

1. 修复 TCP 多 IP 目标的连接超时预算。DNS 查询和所有 IP 尝试继续共用原有总超时；解析完成后，按实际剩余时间及剩余地址数分配单次尝试，避免慢 DNS 或首个不可达 IP 耗尽后续地址的机会。
2. 增加固定 9 类 TCP 失败计数，并在中文运行状态中展示。保留原 JSON 字段和累计失败计数，增加 tcp_failure_reasons，不增加逐连接错误日志。
3. 将真实异常网络测试加入 CI。吞吐测试明确设置自身文件描述符预算，避免 SSH 默认软限制影响比较。

规则格式、配置默认值、UDP/QUIC 转发策略、连接容量计算及系统权限保持兼容。已有 TCP 转发的数据路径未增加逐包工作。

## 生产只读观察

现网为 1 vCPU、约 8 GiB 内存，36 条规则。观察开始时内核 0.1.1 已运行约 13 小时，systemd 自动重启计数为 0。

- 连续 2 分钟、每 20 秒采样：TCP 活跃连接 612–896，进程 CPU 约为单核的 1.5%–2.2%。
- 进程 RSS 约 9.3 MiB，随连接变化的文件描述符能回落；保护状态正常，容量拒绝计数为 0。
- 额外检查 36 条现有规则，36 次 TLS 握手全部成功。配置内容未变。
- 36 个目标都是固定 IPv4 地址。本次复现的 DNS/多地址问题未被证实发生在该生产节点。
- 旧版 tcp_failed 包含准入限制、握手、目标连接和传输中断等原因。不能用这个累计值直接推断目标不可达比例，或据此判断所有失败均由客户端重置引起。
- 本轮生产观察不替代连续数周的运行验证。未在生产节点注入丢包、断网或资源压力。

## 隔离异常网络测试

在开发机使用私有 network/mount namespace 与 veth，分别运行转发器和真实 TCP/TLS/QUIC 后端。tc netem 只作用于测试虚拟网卡；DNS 配置覆盖仅存在于测试挂载空间。未修改宿主机网卡、路由、防火墙、DNS 或现有站点。

| 场景 | 结果 |
| --- | --- |
| 正常 TCP、TLS、QUIC | 通过 |
| 双向 40 ms ±10 ms 延迟、2% 丢包、1% 重复包、20% 乱序 | TCP/TLS/QUIC v1/v2 数据一致 |
| 入口延迟与丢包 | TCP/QUIC 数据一致 |
| 已建立连接遭遇 2 秒完全断网 | 原 TCP/QUIC 会话恢复传输 |
| 目标拒绝连接、不可达、主动 RST | 超时/失败后释放资源，其他目标继续可用 |
| TCP 半关闭、接收背压、客户端握手中途退出 | 数据完整或按故障结束，资源归零 |
| DNS 无响应及 DDNS 地址变化 | 新连接按超时结束；恢复后切换新地址；原连接保持目标 |
| DNS 耗时 1.25 秒，首 IP 无响应，第二 IP 正常，总超时 2 秒 | 0.1.1 失败；0.1.2 约 1.63 秒成功 |
| 总超时 200 ms，前 5 个 IP 无响应，第 6 个正常 | 0.1.1 失败；0.1.2 约 0.17 秒成功 |
| 虚拟网卡连续 3 次 down/up | 恢复后新 TCP/QUIC 会话可用 |
| 路径 MTU 1280 | TLS 与 QUIC 正常传输 |
| TCP 失败原因分类 | 分类符合注入故障，静止后分类合计等于总计 |

每组结束后，活动连接、握手、UDP 队列、来源跟踪数均回到 0；转发器文件描述符回到 13。低流量故障测试未观察到 CPU 空转。测试用 UDP 空闲超时为 4 秒，正式默认仍为 60 秒。

脚本：

~~~bash
python3 -m venv .venv
.venv/bin/pip install aioquic==1.3.0 dnslib==0.9.26
sudo unshare --net --mount --propagation private \
  .venv/bin/python tests/network_faults.py /绝对路径/host-router
~~~

需要 Linux、iproute2 的 ip/tc、util-linux 的 unshare/nsenter 及 netem 支持。脚本拒绝在宿主机初始网络或挂载空间直接运行。测试所需的网卡管理权限只用于隔离测试，正式服务权限未扩大。

## 失败统计含义

status 中的 tcp_failure_reasons 包含：

| 字段 | 含义 |
| --- | --- |
| admission_rejected | 容量、握手额度、总连接或来源 IP 限制拒绝 |
| socket_error | TCP 套接字参数设置失败 |
| handshake_timeout | 等待可识别请求超时 |
| handshake_rejected | 客户端提前断开或请求无法识别 |
| route_missing | 没有匹配的 TCP 规则 |
| dns_error | 系统解析器或内部 DNS 查询返回错误 |
| connect_timeout | DNS 与连接尝试的整体期限或地址连接尝试超时 |
| connect_error | 连接被拒绝、路由错误、自回环保护等 |
| relay_error | 初始数据发送或双向传输中断，包含客户端/目标重置连接 |

准入拒绝发生在 tcp_accepted 增加之前，不能直接用 tcp_failed / tcp_accepted 计算业务错误率。计数为进程启动以来的累计值；并发读取多个原子计数时可能存在瞬间采样差异。不会记录业务数据、客户端地址或目标域名到这些计数中。

## 吞吐与 CPU 对照

环境：开发机 4 vCPU，Rust 2 个工作线程，真实随机文件数据。每组预热 1 秒、测量 5 秒，3 轮交替执行；下表为各指标中位数。两版本测试进程的文件描述符软限制同为 65,536，配置和客户端负载相同。

| 场景 / 指标 | 0.1.1 | 0.1.2 |
| --- | ---: | ---: |
| 16 并发、32 MiB 大块传输 Gbps | 27.30 | 30.52 |
| 大块传输 CPU（单核 = 100%） | 71.93% | 74.81% |
| 大块传输峰值 RSS KiB | 4,640 | 4,576 |
| 128 并发、1 KiB 短连接 次/秒 | 7,521 | 6,758 |
| 短连接 CPU（单核 = 100%） | 147.96% | 150.62% |
| 短连接 P95 ms | 28.03 | 32.52 |

这轮短连接成绩出现约 10% 差异，因此继续进行两项检查，保留全部结果：

- **同版本对照**：两侧均为同一份 0.1.1 二进制，仍出现 8,270 对 7,464 次/秒，约 9.8% 差异，说明该共享虚拟机存在明显测量波动。
- **短连接独立复测**：去除大块传输阶段，另做 3 轮交替对比。0.1.1 为 6,974 次/秒、CPU 151.38%、P95 30.79 ms；0.1.2 为 6,975 次/秒、CPU 151.55%、P95 30.86 ms，基本持平。

上述正式对照与补充测试的请求错误数均为 0。首轮误用 SSH 继承的 1,024 FD 软限制，旧版自动容量保护拒绝部分短连接；该轮没有用于版本性能结论，测试脚本已明确设置自身限额，宿主机全局限制未修改。

本次修复的确定收益是已复现故障下的备用 IP 可达性。没有足够证据宣称吞吐稳定提升或达到任意公网带宽；后续性能判断应在固定资源环境增加更长样本。
