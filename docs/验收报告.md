# 0.1.0 验收记录

日期：2026-10-02。测试在独立监听端口和临时配置下进行，没有更改现有网站、监控服务、系统路由或防火墙。

## 环境与方法

- 开发机：Debian 13，4 vCPU；跨服务器后端：Debian 12。
- 编译器：Rust 1.98.1、Go 1.27.1；生产二进制采用 musl 静态链接。
- Go 基线直接使用原脚本内嵌源码，保留于 `benchmarks/go-original/`，未修改转发逻辑。
- 两个 TCP 内核均使用 2 个调度线程；Rust 的连接上限在压测配置中提高，以免限额影响对比。
- TCP 大流量：16 并发，每次 32 MiB，数据来自真实随机文件；短连接：128 并发，每次 1 KiB。每轮预热 1 秒，采样 5 秒，Go/Rust 交错各测 3 轮，报告中位数。
- QUIC：独立的 Quinn 客户端和服务端，8 个连接共用一个客户端 UDP 端口，启用默认 QUIC Bit GREASE。每次传输 8 MiB，每轮约 10 秒，上下行各 3 轮。
- CPU 100% 表示占满一个逻辑核心；RSS 不包含内核 socket/pipe 缓冲。回环吞吐不代表公网带宽，端点加解密也会竞争这台机器的 CPU。

amd64 文件大小：Go 3,334,304 字节，Rust 2,906,368 字节。ARM64 为交叉编译静态产物，尚未在 ARM 硬件上做同等压测。

下行三轮范围为 1.71–2.40 Gbps，上行为 1.43–1.67 Gbps。相同测试端点直连中位数分别为 4.89、4.64 Gbps，说明端点、转发器及共享 CPU 均影响结果。

## 功能与兼容

已通过：

- HTTP Host、TLS SNI、精确域名、通配域名、IPv6 入口到 IPv4 后端。
- QUIC v1/v2、CRYPTO 分片与乱序、同一客户端 UDP 源端口访问不同域名、QUIC Bit GREASE。
- 普通 UDP 拒绝、无配置路由拒绝、错误 PROXY 输入拒绝。
- IPv4/IPv6 下批量数据报的边界、顺序与完整内容校验。
- DDNS 地址变更后，新 TCP/QUIC 流量切换到新目标，已有 QUIC 会话维持原目标。
- 跨服务器 TLS 4 MiB 数据回显、QUIC v1/v2 各 128 KiB 数据回显，内容一致。
- 批量增删的整体提交、无效编号拒绝、端口占用回滚、配置并发冲突检查、SIGHUP 热加载。
- IPv4 映射 IPv6 地址规范化，自转发目标在建立递归连接前被阻止。
- 私有控制套接字、单实例锁、空闲会话回收、规则与版本菜单展示。
- 原 Go 脚本的真实更新函数迁移到 Rust，规则和目标保留并补全 TCP+UDP。
- 旧更新器再次恢复 root 所有的 JSON 后，服务预处理可正确修复所有权并启动。
- 故意占用 UDP 端口导致升级失败时，原二进制、规则、unit 和 Go 服务运行状态均恢复。

QUIC 仍受可见 SNI、连接 ID 和地址变化的限制；具体边界见 README。普通 UDP 不会自动转发到默认目标。

## 持续负载与内存

每组使用 64 个 TCP 和 32 个 QUIC 并发工作任务，混合长连接与重连，并定期热加载：

- 15 分钟阶段测试：546,792 次 TCP 回显、134,379 次 QUIC 回显、11,162 次重连，错误为 0。
- UDP 大流量优化后的 5 分钟测试：182,112 次 TCP 回显、44,738 次 QUIC 回显、3,754 次重连，错误为 0，RSS 约 5.2–5.5 MiB。
- 最终二进制追加 2 分钟回归：73,092 次 TCP 回显、17,909 次 QUIC 回显、1,549 次重连，错误为 0，结束后资源计数全部回收。
- 24 次配置切换、每代 1,801 条规则且保留各代长连接的专项测试中，连接均继续工作；预热后 RSS 仅增加 712 KiB。
- 流量结束并等待空闲回收后，TCP/UDP 活跃量、排队字节、握手及来源跟踪计数回到 0。

这些记录是短时持续负载验证，不能替代数周真实运行。首次发布后仍应观察机器资源、错误日志及实际链路表现。
