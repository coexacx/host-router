# 部署与旧版迁移

## 新安装

下载发行版中的 `hostip.sh`，以 root 执行 `bash hostip.sh install`。安装器按 CPU 架构下载预编译内核，不会在生产机器上编译 Rust。

Debian / Ubuntu 需安装 `curl ca-certificates passwd util-linux`；RHEL / Rocky / AlmaLinux / Fedora 需安装 `curl ca-certificates shadow-utils util-linux`；Arch Linux 使用 `curl ca-certificates shadow util-linux`。需要 systemd。Alpine 的 OpenRC 服务脚本不在本发行版中，静态内核可手动运行。

在云防火墙与系统防火墙中，按实际规则放行对应的 TCP、UDP 端口。脚本不会清空或自动覆盖已有防火墙规则。

只写端口（例如 `443`）会创建 IPv4、IPv6 监听；仅希望监听 IPv4 可填写 `0.0.0.0:443`。禁止 IPv6 的系统请使用明确的 IPv4 地址。

## 旧 Go 版迁移

旧域名已停用。现在直接切换到本仓库的 GitHub Release，后续更新同样从 GitHub 获取。

旧脚本位于 /root/hostip.sh 时，以 root 逐行执行：

~~~bash
cp -a /root/hostip.sh "/root/hostip.sh.before-rust.$(date +%s)"
sed -i 's#^UPDATE_URL=.*#UPDATE_URL=https://github.com/coexacx/host-router/releases/download/v0.1.2/hostip.sh#' /root/hostip.sh
bash /root/hostip.sh update
~~~

旧更新器会显示下载脚本的 SHA256 并请求确认。可与本次 Release 的 SHA256SUMS 中 hostip.sh 一项核对。非交互更新应明确提供该摘要：

~~~bash
HOSTIP_UPDATE_SHA256=本次发行版hostip.sh的SHA256 bash /root/hostip.sh update
~~~

也可以下载新脚本后执行安装，规则同样会保留：

~~~bash
curl -fL https://github.com/coexacx/host-router/releases/download/v0.1.2/hostip.sh -o /root/hostip.new.sh
bash /root/hostip.new.sh install
install -m 0755 /root/hostip.new.sh /root/hostip.sh
~~~

前一步报错时不要继续覆盖原脚本。安装器会验证二进制摘要，安装成功后才能替换管理脚本。

迁移保留 `listen`、`domain`、`target`、默认目标端口、连接超时等有效配置。旧规则没有 `protocol` 字段时自动使用 `both`，并在成功启动后写回显式 TCP+UDP 规则。

旧更新函数会在安装结束后再次恢复旧 JSON。新服务的启动预处理会校验该文件、修正所属用户，再由内核补全新格式。兼容旧版 `host-router -check -c ...` 校验入口。

## 升级前后的行为

升级内核需要重启，现有连接可能断开后重连。配置规则热更新无需重启。

新增 UDP 监听若与其他程序冲突，升级会失败并回滚；不会抢占其他服务端口，也不会只留下部分启用的规则。请先为冲突规则选择可用端口，再重试。

安装前的内核、规则和 unit 备份位于 `/var/backups/host-router/`，仅 root 可读。部署失败会恢复安装前的文件与服务运行状态。

验证：

```bash
/usr/local/bin/host-router --version
systemctl is-active host-router
/usr/local/bin/host-router -c /etc/host-router/config.json status
journalctl -u host-router -n 50 --no-pager
```

普通 UDP 被拒绝是预期行为。请使用带 SNI 的真实 QUIC 客户端测试 UDP 分流，不能用 UDP ping 或向端口发送随机字符串作为转发成功的判断。

## 常用配置

配置示例见仓库 `config.example.json`。绑定指定 IP 可减少意外暴露。目标使用 IPv6 并包含端口时，采用 `[IPv6]:端口` 写法。

自动容量管理默认开启，检测内存、可用 CPU、cgroup 和文件描述符，按共用预算计算 TCP/QUIC 有效上限；资源紧张时限制新连接，已有会话继续运行。配置中明确填写的数字作为上限保留，手动更改资源字段需要重启。

全新配置的绝对上限为 TCP 65536、QUIC 16384、每 IP 4096、握手 1024、UDP 排队 256 MiB。实际有效值通常更低，不能将 TCP 与 QUIC 的显示额度相加。菜单及 status 可查看实时额度。

识别等待默认 5 秒，QUIC 空闲回收默认 60 秒，单配置最多 4096 条规则。更详细的阈值、CPU 保护、系统预留、手动关闭与故障边界见 [自动容量管理](自动容量管理.md)。

## 安全与发布

配置和本机控制套接字使用私有权限，控制请求有大小与超时限制。在线配置修改具有版本冲突检查。服务只允许使用预先配置的目标，不接受客户端提交任意转发地址。

应用数据不会写入访问日志；访问日志默认关闭。开启日志时，会记录来源地址、匹配域名与目标，请按自己的留存要求管理日志。

后续更新首先验证 Ed25519 签名，再校验脚本与二进制摘要。签名私钥不包含在源码、压缩包或 GitHub 仓库中。TLS 检查不会被关闭。
