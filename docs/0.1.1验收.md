# 0.1.1 验收记录

日期：2026-10-02。测试采用开发机的临时配置、独立端口及临时 cgroup。amd64、arm64 均构建为静态二进制；功能与压测在 amd64 上完成，ARM64 未做硬件实测。

## 自动容量与 CPU 保护

19 项 Rust 单元测试通过，覆盖共用内存/文件描述符预算、剩余内存、启动低内存、cgroup v1/v2 挂载映射、CPU 突发抑制、采样失败关闭准入和渐进恢复。

临时服务限额为 256 MiB MemoryHigh、320 MiB MemoryMax、0.5 CPU、2048 个文件描述符；检测到 TCP 上限 256、QUIC 上限 298，两者受共用预算约束。将该服务的内存软阈值降至 16 MiB 后，新会话额度降为 0，新 TCP 请求被拒绝；3 条已有 TCP、1 条已有 QUIC 继续准确传输。恢复内存后额度逐步回升。

同一临时 cgroup 内的有限 CPU 压力使额度从 30% 降至 22%，压力解除后恢复至 32%，已有会话正常。

30 秒空闲观测中，0.1.0 CPU 约 0.00%，0.1.1 约 0.03%（100% 等于一个核，受内核时钟精度限制）。未观察到资源检测忙循环。

## 0.1.0 与 0.1.1 对比

Debian 13 / 4 vCPU，两个版本各 2 个转发线程，相同规则和配置上限。每次启动预热 1 秒、测量 5 秒，交错测试 3 轮取中位数。大流量为 16 并发、每次 32 MiB 随机数据；短连接为 128 并发、每次 1 KiB。

| 指标 | 0.1.0 | 0.1.1 自动容量 |
| --- | ---: | ---: |
| TCP 大流量吞吐 | 31.03 Gbps | 30.09 Gbps |
| 大流量转发 CPU | 68.87% | 66.69% |
| 大流量峰值 RSS | 4428 KiB | 4508 KiB |
| 大流量 P95 | 264.56 ms | 273.42 ms |
| 短连接处理量 | 7990 次/秒 | 7547 次/秒 |
| 短连接转发 CPU | 153.84% | 157.93% |
| 短连接峰值 RSS | 5360 KiB | 5388 KiB |
| 短连接 P95 | 27.44 ms | 27.52 ms |
| 传输错误 | 0 | 0 |

本组新版大流量吞吐约低 3.0%，短连接量约低 5.5%；短连接每请求 CPU 开销有所增加。保护机制有准入检查成本，不能宣称全面提速。回环和共享 CPU 测量有波动，不代表公网带宽或所有工作负载。

## QUIC、持续负载与热加载

独立 Quinn 客户端/服务端，8 个连接共享客户端 UDP 源端口，每次 1 MiB 随机数据，上下行分别测量约 10 秒。本轮下行 2.11 Gbps、上行 1.91 Gbps，转发 CPU 分别约 72.96%、72.43%，传输错误和用户态队列丢包均为 0。每个方向仅一轮，不作为长期性能排名。

120 秒混合持续测试使用 64 个 TCP、32 个 QUIC 工作任务，混合长连接、重连和周期热加载：73123 次 TCP 数据交换、17947 次 QUIC 数据交换、1552 次重连，错误为 0；结束后会话、排队字节、握手和 IP 记录均释放。RSS 约 5.2–5.5 MiB。

24 代热加载，每代 1801 条规则并保留旧连接，全部连接正常；预热后 RSS 增量 708 KiB。

## 功能、安全与迁移

全部通过：

- HTTP Host、TLS SNI、通配规则、IPv6、QUIC v1/v2、分片乱序及同源端口多域名。
- 普通 UDP 拒绝、20000 个异常 UDP 数据报后健康检查、自转发防护、PROXY 输入拒绝。
- 批量增删、事务回滚、并发冲突、SIGHUP、单实例及资源回收。
- 私有挂载命名空间中的 DDNS 更新：新会话切换 IP，已有 QUIC 保持旧目标。
- 真实旧 Go 更新函数迁移至 0.1.1，保留规则并补全 TCP+UDP。
- 故意占用 UDP 端口后，安装失败回滚原二进制、JSON、unit 与 Go 服务；旧更新器恢复 root 所有的 JSON 后仍可正常启动。
- 发布签名、篡改清单、伪造签名、外站地址及版本降级分类。
- cargo fmt、Clippy（警告视为错误）、ShellCheck。
- cargo audit 已知漏洞 0，告警 0。
- 待发布源码未发现部署密码、GitHub token 或签名私钥；压缩包只包含受版本管理的文件。

审阅了新会话资源释放、采样线程隔离、预算竞争、cgroup 层级和热更新生命周期。本次测试未发现改动引入的安全问题，不代表没有未知漏洞；120 秒持续测试也不等于长期稳定性证明。MemoryMax 在异常情况下仍可能导致本服务重启，详见 [自动容量管理](自动容量管理.md)。
